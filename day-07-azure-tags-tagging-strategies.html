The concept

Tags are name and value pairs you attach to resources, resource groups, subscriptions, and management groups. They are metadata: they change nothing about how a resource runs, but they change everything about how you manage it.

3 jobs tags do:

  • Cost allocation. Group and filter costs in Cost Management by tag. Department: Cardiology lets finance see exactly what cardiology's cloud spend is. This is chargeback and showback in practice.
  • Operations. Environment: Prod, Owner: amara@meridianhealth.org, Application: PatientPortal. When something breaks at 2 in the morning, tags tell you who owns it and how critical it is.
  • Governance. Azure Policy can require tags, append missing tags, or inherit a tag from the parent resource group (Days 11 to 14 build on this).

The rules and the trap:

  • Maximum 50 tags per resource, resource group, or subscription. Tag names allow up to 512 characters, values up to 256.
  • Tag names cannot contain these characters: < > % & \ ? /.
  • The trap: tags are NOT inherited automatically. Tagging a resource group Environment: Prod does not tag the VMs inside it. This is the number 1 tags question on the exam. To enforce tags, use Azure Policy: the built-in "Require a tag and its value" blocks noncompliant deployments, and "Inherit a tag from the resource group" stamps the parent's tag onto new resources.

A solid tagging strategy is small and enforced: 4 to 6 tags, documented, required by policy. Common set: Environment, Department or CostCenter, Owner, Application, and DataClassification.

Key vocabulary

  • Tag: a name and value pair attached to an Azure resource, resource group, subscription, or management group.
  • Chargeback / showback: billing the cost back to departments (chargeback) or just reporting it (showback). Tags make both possible.
  • Inheritance (tags): does not happen automatically. Policy is the enforcement mechanism.
  • Tagging strategy: the documented standard of which tags are required and what values are allowed.

Try it

Tags are free. You will tag a lab resource group, verify with the CLI, then delete it.

In the portal:

  1. Search for Resource groups and open rg-az104-day04 if it still exists from Day 4. If you deleted it, create it again quickly (same name, East US).
  2. Open Tags in the left menu. Add 2 tags: Environment = Lab and Owner = your name or Study. Click Apply.
  3. Open Cost Management from the resource group menu and note that you can group costs by tag. Your empty group costs nothing, but the grouping option is there.

In the CLI (Cloud Shell is fine):

  1. Create a tagged group: az group create --name rg-az104-tags --location eastus --tags Environment=Lab Owner=Study.
  2. Read the tags back: az group show --name rg-az104-tags --query tags --output table.
  3. Clean up: az group delete --name rg-az104-tags --yes and delete rg-az104-day04 if you recreated it.

Clean up: both lab resource groups deleted. Tags vanish with the resource they are attached to.

Worked example: Meridian Health

Meridian Health's tagging standard has 5 required tags: Environment, Department, CostCenter, Owner, DataClassification. Finance runs chargeback per Department tag every month. 2 policies enforce it: "Require a tag and its value on resources" blocks any deployment missing Environment, and "Inherit a tag from the resource group" stamps CostCenter from the resource group onto every new resource. When auditors ask which resources hold patient data, the team filters by DataClassification: PHI instead of guessing.

  4. How do you force every new storage account to carry a Department tag?

Exam tip

The inheritance trap is the number 1 tags question: tags never flow down on their own. If the scenario says "ensure all resources carry the CostCenter tag," the answer is Azure Policy, not manual tagging. The built-in policies to name are "Require a tag and its value" and "Inherit a tag from the resource group."

Key takeaways

  • Tags are name and value metadata used for cost allocation, operations, and governance.
  • Limits: 50 tags per scope, 512 character names, 256 character values, no < > % & \ ? / in names.
  • Tags are NOT inherited automatically. Enforce them with Azure Policy.
  • Keep the strategy small (4 to 6 tags), documented, and policy enforced.
