The concept

Creating users 1 at a time (Day 23) does not survive contact with a 500-person hiring wave. Entra ID gives you 2 bulk paths:

Bulk create / bulk invite in the portal. Under Identity > Users > All users, the Bulk create button downloads a CSV template. You fill in 1 row per user (name, UPN, initial password, block sign-in flag, usage location are the columns that matter), upload it, and Entra ID creates every account. Bulk invite does the same for guest users (Day 25). Each upload runs as a bulk job, and Bulk operation results shows you which rows succeeded and which failed, with reasons. Failed rows do not roll back the successes: you fix the rows and re-upload just those.

Scripted with PowerShell and Microsoft Graph. For repeatable onboarding, admins script it: read the CSV with Import-Csv and call New-MgUser once per row. Same result as the portal upload, but it lives in source control and runs on a schedule. The exam treats both as valid; it tests that you know bulk operations exist and where the job results live.

3 rules that catch people:

  1. The CSV template is picky. Use the downloaded template, do not hand-roll the headers, and keep the required columns filled.
  2. UPNs must be unique and on verified domains. Duplicates are the number 1 bulk failure.
  3. Usage location is still required per user before licenses can be assigned. Bulk create does not skip Day 23's rules.

Key vocabulary

  • Bulk create: portal job that creates many member users from a CSV upload.
  • Bulk invite: portal job that invites many guest users from a CSV upload.
  • Bulk operation results: the job history page showing per-row success and failure reasons.
  • Microsoft Graph: the API behind Entra ID. PowerShell's New-MgUser and portal clicks both end up here.

Try it

Free. You create 2 throwaway users and delete them at the end.

In the portal:

  1. In the Microsoft Entra admin center, open Identity > Users > All users > Bulk create. Download the CSV template.
  2. Add 2 rows with the required columns filled: distinct display names, UPNs like bulktest1@<your-tenant>.onmicrosoft.com, initial passwords, usage location set, block sign-in set to No.
  3. Upload the CSV. Open Bulk operation results and confirm both rows show success. Note the job details: this is your audit trail.
  4. Open All users and confirm the 2 accounts exist. Select both, click Delete. Confirm they are gone.

With PowerShell (Microsoft Graph module, alternative path):

  1. The repeatable version of the same job: Import-Csv reads your CSV, then a loop calls New-MgUser once per row with the display name, UPN, password profile, and account status from that row's columns.
  2. Verify in All users that the accounts landed, then delete them as in step 4 above.

Clean up: both test users deleted. The bulk job records in Bulk operation results remain as history; they cost nothing.

Worked example: Meridian Health

Meridian Health acquires a 40-person clinic. HR exports the roster as a spreadsheet. The admin downloads the bulk create template, maps the HR columns to it, and uploads 40 rows. The job result shows 38 successes and 2 failures: both failures are duplicate UPNs from 2 hires with the same name. The admin fixes the 2 UPNs, re-uploads just those rows, and all 40 accounts exist within the hour. Usage location was filled for every row, so licensing (a P1 task for another day) will not hit the Day 23 gotcha.

Check your understanding

  1. Where do you check which rows of a bulk upload failed, and why?
  2. Your bulk upload shows 45 successes and 5 failures. Do the 45 get rolled back?
  3. Name 2 columns that commonly cause bulk create failures.
  4. HR will send a new-hire spreadsheet every Monday. Portal clicks or script: which scales, and with what cmdlet?

Exam tip

The exam asks "how" for bulk user creation in exactly 2 ways: the portal CSV upload (bulk create / bulk invite) and PowerShell with Microsoft Graph. If the scenario mentions hundreds of users or a recurring process, the scripted path is the intended answer.

Key takeaways

  • Bulk create (members) and bulk invite (guests) run from CSV uploads under Users > All users.
  • Always use the downloaded template; UPNs must be unique and on verified domains.
  • Bulk operation results is the per-row success and failure log; failures do not roll back successes.
  • For repeatable onboarding, script it: Import-Csv plus New-MgUser per row.
  • Bulk operations still follow the Day 23 rules: usage location before licenses, 30 day restore on delete.
