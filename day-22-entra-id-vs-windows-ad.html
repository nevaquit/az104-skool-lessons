The concept

New admins mix these up because the names overlap. They are different products solving different problems.

Windows Server Active Directory is the on-premises directory: domain controllers on your servers, speaking LDAP, Kerberos, and NTLM. It is hierarchical: forests contain domains, domains contain organizational units (OUs), and Group Policy hangs off OUs to push settings to machines. It authenticates users to the corporate network and to legacy apps.

Microsoft Entra ID is the cloud directory: no servers to run, speaking web protocols: SAML, WS-Federation, OAuth 2.0, and OpenID Connect. It is flat: there are no OUs. Organization happens with groups and administrative units (Day 39). There is no Group Policy; device and app control moves to Intune and Conditional Access.

The comparison the exam wants:

Where it runsYour domain controllersMicrosoft cloud

2 bridge facts:

  • Hybrid identity (Days 35-37) syncs on-prem AD users into Entra ID with Entra Connect, so 1 identity works in both worlds.
  • Microsoft Entra Domain Services adds managed LDAP, Kerberos, and Group Policy-like support in Azure for legacy apps that cannot speak modern protocols. If an exam question says "lift and shift an app that requires LDAP," Domain Services is the answer, not plain Entra ID.

Key vocabulary

  • Organizational unit (OU): a container inside Windows Server AD used to organize users and link Group Policy. Does not exist in Entra ID.
  • Kerberos / NTLM: on-premises authentication protocols. Cloud apps use OAuth 2.0 and OpenID Connect instead.
  • SAML: the XML-based SSO protocol most enterprise SaaS apps use with Entra ID.
  • Hybrid identity: 1 user identity working across on-premises AD and Entra ID, synced by Entra Connect.
  • Microsoft Entra Domain Services: managed domain services in Azure giving LDAP, Kerberos, and Group Policy support to legacy apps.

Try it

Read-only. Nothing is created or changed.

In the portal:

  1. In the Microsoft Entra admin center, open Identity > Users > All users and click any user. Look at the available fields: user principal name, usage location, assigned groups and roles. Notice what is missing: there is no OU path and no Group Policy tab. That is the flat model.
  2. Open Identity > Groups > All groups. Groups are the Entra ID answer to "how do I organize users": access, licensing, and policy all key off groups.
  3. If you have access to an on-premises or hybrid lab, open Active Directory Users and Computers on a domain controller or RSAT machine and expand the domain: forests, OUs, Group Policy links. Contrast it with step 1.

In the CLI:

  1. View a user's cloud attributes: az ad user show --id <user-principal-name> --query "{upn:userPrincipalName, type:userType}" --output table. No OU, no GPO references: just cloud attributes.

Worked example: Meridian Health

Meridian Health still runs Windows Server AD in its hospital data center for the old radiology system, which authenticates with Kerberos and is managed with Group Policy. New cloud apps (the patient portal, Microsoft 365) authenticate against Entra ID with SSO. Entra Connect syncs the hospital staff accounts so a nurse uses 1 identity in both places. When the radiology vendor finally ships a SAML-capable version, Meridian will point it at Entra ID and retire that piece of the on-premises domain. Until then, the rule holds: legacy protocols stay on Windows Server AD or Domain Services; everything modern goes to Entra ID.

Check your understanding

  1. An application authenticates with LDAP and cannot be rewritten. Which Azure service lets it run in the cloud?
  2. In Entra ID, you need 1 policy to reach 500 users. Do you use an OU or something else?
  3. A company wants Group Policy for its cloud-only laptops. What is the Microsoft cloud answer?
  4. Which 2 protocols does Entra ID use for modern SSO?

Exam tip

Protocol questions are free points if you memorize the split: LDAP, Kerberos, and NTLM mean Windows Server AD; SAML, OAuth 2.0, and OpenID Connect mean Entra ID. Any question with "on-premises application that requires Kerberos" is pointing at Entra Connect authentication or Domain Services, never plain Entra ID.

Key takeaways

  • Windows Server AD: on-premises, hierarchical (forests, domains, OUs), LDAP/Kerberos/NTLM, Group Policy.
  • Entra ID: cloud, flat (groups, administrative units), SAML/OAuth 2.0/OpenID Connect, Conditional Access and Intune instead of Group Policy.
  • Hybrid identity with Entra Connect gives 1 identity in both worlds.
  • Legacy apps needing LDAP or Kerberos in Azure use Microsoft Entra Domain Services.
