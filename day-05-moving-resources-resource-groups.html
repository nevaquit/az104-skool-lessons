The concept

Resources are not stuck where they were born. Azure lets you move resources between resource groups, and even between subscriptions, as long as a few rules hold.

The move rules:

  1. Same tenant. The source and destination must be in the same Microsoft Entra tenant. Cross tenant moves are not supported.
  2. Not every resource type supports moving. Each resource provider declares whether its resources can move. Always check move support for the specific type before you plan a move.
  3. Some resources cannot move at all while in use. A Recovery Services vault with protected backup items cannot move. Virtual networks with active peerings need care. App Service plans have their own restrictions.
  4. Some resources must move together. A VM move typically includes its disks and network interface. The portal's move blade tells you what must travel as a group.
  5. Validation runs first. When you start a move, Azure validates every selected resource and reports which ones can move before anything changes.
  6. Resources are locked during the move. Reads and writes are blocked while the move executes, so plan for a brief outage window.

The portal flow: open the resource group, select the resources, click Move, then choose "Move to another resource group" or "Move to another subscription." Read the validation results carefully, then confirm. Moving to another subscription also changes the billing boundary from Day 2, so finance usually wants a say.

Key vocabulary

  • Move operation: relocating a resource to a different resource group or subscription.
  • Validation: the pre-move check Azure runs to confirm every selected resource supports the move.
  • Move support: a per resource type declaration of whether moves are allowed.
  • Tenant boundary: moves are only allowed within a single Microsoft Entra tenant.

Try it

This lab is observational on purpose: you will walk up to the move blade, read the validation, and cancel before anything moves. Nothing changes and nothing is billed.

In the portal:

  1. Search for Resource groups and open the group that holds your Cloud Shell storage (its name starts with cloud-shell-storage).
  2. Select the storage account inside it, then click Move in the top bar and choose Move to another resource group.
  3. Read the blade: it shows the source, lets you pick a destination, and will run validation listing which selected resources support the move. Do not pick a destination. Close the blade with Cancel.

In the CLI (Cloud Shell is fine):

  1. List a resource ID you could theoretically move: az resource list --query "[0].{name:name, id:id}" --output table.
  2. Read the move command's options without executing anything: az resource move --help. Note the --destination-group and --ids parameters.

Clean up: nothing was moved. Confirm your Cloud Shell storage account is still in its original resource group.

Worked example: Meridian Health

A junior admin deploys a storage account holding patient exports into rg-patientportal-dev by mistake. It belongs in rg-patientportal-prod. The senior admin opens the dev resource group, selects the storage account, clicks Move, and reads the validation: the storage account supports the move. She moves it to the prod group during a maintenance window, because the account is briefly locked during the move. Lesson learned: the team adds a "check the resource group" step to their deployment checklist.

Check your understanding

  1. Can you move a resource to a subscription in a different Microsoft Entra tenant?
  2. What does Azure run before a move is allowed to complete?
  3. A Recovery Services vault has active backups. Can it be moved to another resource group?
  4. What happens to a resource while the move is executing?

Exam tip

2 move facts cover nearly every exam question: moves stay inside 1 tenant, and you must check per resource type move support. "Which of these resources can be moved" questions are really "which provider supports move" questions. Backup vaults with protected items are the classic "cannot move" answer.

Key takeaways

  • Resources can move between resource groups and between subscriptions within the same tenant.
  • Azure validates every selected resource before anything moves; not all types support it.
  • Some resources must move as a group; some cannot move while in use.
  • Resources are locked during the move, so plan a maintenance window.
  • Moving to another subscription changes the billing boundary.
