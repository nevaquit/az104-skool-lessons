The concept

Users are the most basic identity in Entra ID, and the exam expects you to know their full lifecycle: create, configure, block, delete, restore.

Creating a user. You supply a display name and a user principal name (UPN), which looks like an email address: nurse.lee@meridianhealth.onmicrosoft.com. The UPN must use a domain verified in the tenant. You also set the usage location, a required field before any license can be assigned (Microsoft needs it for legal reasons around where services run). Password: let Azure generate 1 or set your own.

User types. A Member is a normal user of your organization. A Guest is an external B2B user (Day 25). Members get full directory access by default; guests get limited access.

Blocking sign-in. Every user has a "Block sign-in" toggle in their profile. Suspect a compromised account? Block sign-in first, investigate second. It takes effect quickly and beats deleting the account, because deletion destroys group memberships and role assignments you may want to keep.

Deleting and restoring. Deleted users go to Deleted users, where they sit for 30 days and can be restored with everything intact. After 30 days they are gone permanently. The exam loves this: "a user was deleted 10 days ago, how do you recover access" is always "restore from Deleted users."

Directory roles. Users get permissions through Microsoft Entra roles (Global Administrator, User Administrator, Billing Administrator, and others). Global Administrator is the keys to the kingdom: limit it to a handful of break-glass accounts. This connects straight back to RBAC (Days 15-20): Entra roles govern the directory, Azure RBAC roles govern resources.

Key vocabulary

  • User principal name (UPN): the sign-in name for a user, in email format. Must use a verified domain.
  • Usage location: the country or region set on a user, required before licenses can be assigned.
  • Member vs Guest: Member is an organization user; Guest is an external B2B user with limited directory access.
  • Block sign-in: instantly prevents a user from signing in without deleting the account.
  • Deleted users: the recycle bin for identities. Restorable for 30 days.

Try it

You need a test user. Everything here is free; the user is deleted at the end.

In the portal:

  1. In the Microsoft Entra admin center, open Identity > Users > All users > New user > Create new user.
  2. Enter a display name like Lab Test User, a UPN like labtest.user@<your-tenant>.onmicrosoft.com, and set the usage location to your country. Let Azure auto-generate the password and note it.
  3. Open the new user, then Edit properties. Toggle Block sign-in to Yes, save, then set it back to No. This is the incident response move.
  4. Delete the user (Delete on the user page). Then open Identity > Users > Deleted users, select the user, and Restore. Confirm the user is back in All users with memberships intact.
  5. Delete the user 1 final time to clean up. It will purge automatically after 30 days.

In the CLI (Cloud Shell is fine):

  1. Create the test user: az ad user create --display-name "Lab Test User" --user-principal-name "labtest.user@<your-tenant>.onmicrosoft.com" --password "<a-strong-throwaway-password>".
  2. View it: az ad user show --id "labtest.user@<your-tenant>.onmicrosoft.com" --query "{upn:userPrincipalName, enabled:accountEnabled}" --output table.
  3. Delete it: az ad user delete --id "labtest.user@<your-tenant>.onmicrosoft.com".

Clean up: the test user is deleted (portal steps) or delete it now with the CLI command in step 3. Nothing billable was created.

Worked example: Meridian Health

Meridian Health onboards 12 new nurses. The helpdesk creates each account with the UPN format firstname.lastname@meridianhealth.org, sets usage location to United States, and assigns the Microsoft 365 license. 1 nurse's credentials are phished on day 3: the admin blocks sign-in on the account in under a minute, forces a password reset, then unblocks it. When a traveling doctor leaves, the admin deletes the account; 2 weeks later the doctor returns on contract and the account is restored from Deleted users with all group memberships intact. No rebuild, no drama.

Exam tip

"Usage location required before license assignment" is a classic gotcha: the license assignment fails and the fix is 1 field on the user. Also memorize the 30 day restore window for deleted users; the exam frames it as "accidentally deleted last week."

Key takeaways

  • Create users with a display name, a UPN on a verified domain, and a usage location.
  • Block sign-in for compromised accounts; it is faster and safer than deleting.
  • Deleted users are restorable for 30 days from Deleted users.
  • Members are organization users; Guests are external B2B users.
  • Entra directory roles (like Global Administrator) govern the directory; Azure RBAC roles govern resources.
