The concept

Entra ID roles like User Administrator are powerful, and by default they apply to the entire tenant. But most organizations do not want the Boston helpdesk resetting passwords for the Seattle office. Administrative units solve this: they let you delegate administration over a slice of the directory instead of the whole thing. This requires a Microsoft Entra ID P1 license.

How it works, in 3 steps:

  1. Create the administrative unit in the Entra admin center under Identity > Roles and admins > Admin units. Give it a clear name like AU-North-Region.
  2. Add members: users, groups, or devices that belong to that slice. Membership can be assigned manually or driven by dynamic rules (a P1 feature, same engine as dynamic groups from Day 27).
  3. Assign roles scoped to the unit: pick a role such as User Administrator or Groups Administrator and scope the assignment to the AU. That admin can now manage only the AU's members: nothing more.

The exam's framing: administrative units are the answer to "delegate administration for part of the organization without creating a second tenant." Before AUs existed, the only clean way to do that was another tenant, with all the duplicated licensing and management that implies.

1 advanced variant: the restricted management administrative unit. It is extra locked down and used for the most sensitive role assignments, typically managed through Privileged Identity Management (which needs P2). You will meet PIM in the deep-dive module; for now, know that restricted management AUs exist for protecting tier-zero roles.

Keep the 2 scoping systems straight, because the exam mixes them deliberately:

  • Azure RBAC scoping (Days 15-20): management group, subscription, resource group, resource. This governs Azure resources.
  • Entra role scoping with AUs (this lesson): administrative units. This governs directory objects like users and groups.

Key vocabulary

  • Administrative unit (AU): a container for delegating administration over part of the directory (requires P1).
  • Scoped role assignment: an admin role that applies only inside an AU, not tenant-wide.
  • Restricted management administrative unit: a locked-down AU for highly privileged role assignments.
  • Delegated administration: giving part of the admin job to someone else, limited to their slice.

Try it

You will create a real AU and then remove it. Role assignment to an AU needs P1; without a trial license, walk through the UI read-only.

In the portal:

  1. Microsoft Entra admin center > Identity > Roles and admins > Admin units. Review any existing units and their member counts.
  2. Select + Add, name it "AU-Lab-Test", and add your own user account as a member.
  3. Open the new AU, go to Roles and administrators, and assign yourself the User Administrator role scoped to this AU.
  4. As the scoped admin, open Users and confirm you can manage AU members. Try viewing a user outside the AU to feel the boundary.
  5. Compare with an Azure RBAC assignment (Day 19): note that the scope dropdown here offers the AU, not a subscription.

Clean up: remove the role assignment, remove yourself as a member, then delete "AU-Lab-Test". Verify the Admin units list is back to its original state.

Worked example: Meridian Health

Meridian Health creates 3 administrative units: AU-North, AU-South, and AU-Central, each holding that region's users and groups. Each region's IT lead receives the User Administrator and Groups Administrator roles scoped to their AU. A lead in the north can reset passwords and manage groups for northern clinics, and has zero visibility into southern user accounts. The tenant-wide admin team shrinks to 4 people, and the auditors get a clean report: every admin's reach is documented in the AU assignments.

Exam tip

"Delegate administration for a subset of users without creating another tenant" is the trigger phrase for administrative units. The exam also tests that you keep the 2 scoping systems apart: AUs scope Entra directory roles, while management groups down to resources scope Azure RBAC roles. A question that mixes them is checking exactly that.

Key takeaways

  • Administrative units delegate administration over part of the directory (P1 required).
  • Create the AU, add members, then assign roles scoped to it.
  • Dynamic membership rules can populate AUs automatically.
  • Restricted management AUs add extra protection for the most privileged roles.
  • Never confuse AU scoping (directory objects) with Azure RBAC scoping (Azure resources).
