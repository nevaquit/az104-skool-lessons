The concept

Devices get identity objects in Microsoft Entra ID so that access decisions can consider device health, not just user credentials. A sign-in from a compliant corporate laptop and a sign-in from an unknown phone stop looking the same to the system.

There are 3 device states:

  • Microsoft Entra registered: a personal device (phone, home laptop) where the user adds a work account. This is the BYOD state, sometimes called workplace join. Management is light.
  • Microsoft Entra joined: a corporate device joined directly to the cloud directory. No on-premises Active Directory involved. Managed with Intune.
  • Microsoft Entra hybrid joined: a device joined to on-premises Active Directory and also registered in Entra ID. The bridge state during migration (deep dive on Day 33).

You manage them in the Microsoft Entra admin center under Identity > Devices > All devices. The columns that matter:

  • Join type: registered, Entra joined, or hybrid joined.
  • Owner: who the device is registered to.
  • MDM: which management tool owns it (Intune, or none).
  • Compliant: whether it meets your compliance policies.

Device lifecycle actions: disable a device to block its access immediately (the move for a lost laptop), and delete stale device objects to keep the directory clean. Note the trap: a deleted device must re-register before it can get access again, so delete only devices that are truly retired.

Why the exam cares: device objects are what make device-based Conditional Access possible. A policy that says "require a compliant device" can only work if the device has an identity and Intune has marked it compliant.

Key vocabulary

  • Device object: the identity record for a device in Entra ID.
  • Microsoft Entra registered: BYOD state; user adds a work account to a personal device.
  • Microsoft Entra joined: corporate device joined directly to the cloud directory.
  • Microsoft Entra hybrid joined: device joined to on-premises AD and registered in Entra ID.
  • MDM (Mobile Device Management): Intune in the Microsoft world; enforces compliance and deploys apps.
  • Compliance: the device meets your policies (encryption on, OS patched, PIN set).
  • Stale device: a device object with no recent activity; a cleanup target.

Try it

Read-only lab. Do not disable or delete any real device.

In the portal:

  1. Open the Microsoft Entra admin center and go to Identity > Devices > All devices. Compare the Join type column across devices.
  2. Open 1 device and note its Device ID, join type, owner, MDM authority, and last activity timestamps.
  3. Go to Identity > Devices > Device settings and check 2 settings: who is allowed to join devices to Entra ID, and whether users may register their personal devices.

CLI alternative:

az ad device list --query "[].{Name:displayName, JoinType:trustType, Enabled:accountEnabled}" --output table

The trustType values map to the portal states: Workplace means registered, AzureAd means Entra joined, ServerAd means hybrid joined.

Clean up: nothing was created or changed.

Worked example: Meridian Health

Meridian Health's device picture:

  • Corporate laptops: Entra joined, Intune managed, marked compliant. These satisfy the Conditional Access policy guarding the patient records app.
  • Doctors' personal tablets: registered (BYOD). They get email and Teams, but the patient records app stays blocked because the devices are not compliant.
  • Old imaging workstations: hybrid joined during the migration off on-premises AD.

When a nurse reports a lost laptop, the helpdesk disables its device object within minutes. The finder cannot get past the sign-in screen even with the correct password, because the device identity is disabled.

Check your understanding

  1. A doctor wants to read email on a personal phone. Which device state fits, and why not Entra joined?
  2. What happens when you disable a device object in Entra ID?
  3. Which tool marks a device as compliant so Conditional Access can trust it?
  4. True or false: a hybrid joined device is joined to on-premises AD and registered in Entra ID.

Exam tip

Match the device state to the scenario: BYOD and personal devices mean registered; corporate cloud-native devices mean Entra joined; migration from on-premises AD means hybrid joined. If a question says "require a compliant device," the device must be Intune managed, because only Intune evaluates compliance.

Key takeaways

  • Devices have identity objects in Entra ID in 3 states: registered, Entra joined, hybrid joined.
  • Device objects are what make device-based Conditional Access possible.
  • Disable blocks a lost device immediately; delete retires it permanently (it must re-register).
  • Intune owns compliance; only compliant devices satisfy "require compliant device" policies.
