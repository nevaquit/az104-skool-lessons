The concept

Knowing the roles is half the skill; granting them correctly is the other half. Every assignment picks 3 things: the role, the principal, and the scope. The portal walkthrough is Access control (IAM), Add, Add role assignment, then 3 tabs:

  1. Role: pick the job function, such as Reader or Virtual Machine Contributor. The portal shows what each role allows before you commit.
  2. Members: pick who gets it: a user, an Entra group, a service principal, or a managed identity. Groups are the best practice because membership changes in Entra ID automatically change access, with no assignment to touch.
  3. Review + assign: confirm and create.

3 assignment truths for the exam:

  • Scope inheritance does the heavy lifting. 1 Reader assignment at the subscription covers every current and future resource group and resource inside it. Assign at the broadest scope the requirement allows, but no broader.
  • Privileged roles should be eligible, not permanent. Through PIM, an assignment can be eligible: the user activates it just in time with a reason, approval, and expiry, instead of holding Owner 24 hours a day.
  • Propagation takes time. A new assignment can take several minutes to take effect everywhere. If access looks wrong 2 minutes after assigning, wait before troubleshooting (Day 20).

To verify what someone actually has, use the Check access tab in Access control (IAM): search the user or group and see every effective assignment, including inherited ones and any deny assignments.

Key vocabulary

  • Eligible assignment: a PIM assignment the user must activate before it takes effect.
  • Active assignment: a standing assignment that applies immediately.
  • Propagation: the delay before a new or changed assignment takes effect everywhere.
  • Check access: the IAM tool that shows a principal's effective permissions.

Try it

You need any Azure account, including a free 1. You will create a real assignment and then remove it, so nothing is left behind.

In the portal:

  1. Pick a lab resource group and open Access control (IAM), then Add, then Add role assignment.
  2. On the Role tab, select Reader. On the Members tab, select an Entra group you control. Review and assign.
  3. Open the Check access tab, search the group, and confirm the Reader assignment appears, including its scope.
  4. Go back to the Role assignments tab, select the assignment you just made, and choose Remove.

In the CLI (Cloud Shell is fine):

  1. Create the assignment: az role assignment create --assignee "<group-object-id>" --role "Reader" --resource-group "<rg-name>"
  2. Verify it: az role assignment list --resource-group "<rg-name>" --output table
  3. Remove it: az role assignment delete --assignee "<group-object-id>" --role "Reader" --resource-group "<rg-name>"

Clean up: the assignment was removed in step 4. Confirm it is gone using Check access.

Worked example: Meridian Health

Meridian's auditors need read access to production for a quarterly review. The cloud admin opens the Meridian-Prod subscription, goes to Access control (IAM), adds a role assignment: role Reader, member the "Auditors" Entra group, scope the subscription. 1 assignment covers every resource group in the subscription through inheritance, including ones created next month. When the review ends, the admin removes the single assignment. No per-resource work, no leftover access, and the whole thing is visible in Check access for the audit trail.

Exam tip

"Grant X the ability to do Y on Z" is always a role assignment question: name the role (Y), the principal (X), and the narrowest scope (Z) that satisfies the requirement. If the scenario mentions temporary or approved privileged access, add PIM eligibility to your answer.

Key takeaways

  • An assignment is role plus principal plus scope, created under Access control (IAM).
  • Assign to Entra groups, not individuals, so membership changes carry access with them.
  • 1 assignment at a parent scope covers everything below it through inheritance.
  • Make privileged assignments eligible through PIM instead of permanent.
  • New assignments need several minutes to propagate; verify with Check access.
