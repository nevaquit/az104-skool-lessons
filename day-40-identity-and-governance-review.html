What this module covered

You have finished the highest-weight domain on the exam. Here is the whole module in 1 page, in 2 halves.

Governance (Days 2-20): controlling cost, access, and compliance at scale.

  • Days 2-4: The hierarchy. Subscriptions are the billing and access boundary; management groups govern subscriptions at scale; resource groups organize resources inside a subscription.
  • Day 5: Moving resources between resource groups and subscriptions, and what breaks when you do (the resource keeps working, but update your references).
  • Days 6-10: Cost control. Quotas apply per subscription per region; tags drive chargeback; Cost Management shows where money goes; budgets and alerts cap spend; Azure Advisor recommends savings.
  • Days 11-14: Azure Policy. Definitions state the rule, assignments apply it at a scope, initiatives bundle definitions, and compliance reports show what drifts.
  • Days 15-20: RBAC. Built-in roles (Owner, Contributor, Reader), custom roles for the gaps, assignments at 4 scopes, and troubleshooting with effective permissions. And the golden distinction: RBAC controls who can do what; Policy controls what is allowed to exist.

Identity (Days 21-39): the people and devices behind every access decision.

  • Days 21-22: Microsoft Entra ID is the cloud identity plane; it is not Windows Server AD with a new name.
  • Days 23-27: Users, bulk operations, B2B guests, groups, and dynamic groups that fill themselves by rule.
  • Days 28-30: Securing sign-in basics: self-service password reset, multifactor authentication, and Security Defaults for tenants without P1.
  • Day 31: Conditional Access, the Zero Trust if-then engine: assignments plus grant and session controls, tested in Report-only, with a break-glass account always excluded.
  • Days 32-33: Device identities: registered for BYOD, Entra joined for cloud-native fleets, hybrid joined for migration. dsregcmd /status tells the truth.
  • Day 34: Custom domains so sign-in names match email, proven with a DNS TXT record.
  • Days 35-37: Hybrid identity with Entra Connect. 1 bridge, 3 sign-in methods: password hash sync (cloud validates, resilient), pass-through authentication (on-premises validates, policy control), federation (full control, most complex).
  • Day 38: Identity Protection (P2): sign-in risk and user risk, automated responses, investigation in the risky blades.
  • Day 39: Administrative units (P1): delegate administration over part of the directory without a second tenant.

Vocabulary drill

Read the term, say the definition from memory, then check yourself.

  • Subscription: the billing boundary and a primary access boundary; all usage meters to exactly 1 subscription.
  • Management group: container above subscriptions for governance at scale.
  • Resource group: logical container for resources inside a subscription.
  • Azure Policy: enforces what is allowed to exist (compliance guardrails).
  • Initiative: a bundle of policy definitions assigned together.
  • RBAC: controls who can do what, assigned at management group, subscription, resource group, or resource scope.
  • Custom role: a user-defined set of permissions for gaps the built-in roles do not cover.
  • Microsoft Entra ID: the cloud identity and access plane; not the same product as Windows Server AD.
  • UPN: the sign-in name, shaped like an email address.
  • B2B guest: an external user invited into your tenant with limited access.
  • Dynamic group: membership computed from attribute rules (requires P1).
  • SSPR: self-service password reset; writeback to on-premises needs P1.
  • MFA: multifactor authentication: something you know plus something you have or are.
  • Security Defaults: baseline protections (including MFA for admins) for tenants without P1.
  • Conditional Access: if-then Zero Trust policies evaluated at every sign-in (requires P1).
  • Named location: trusted IP ranges or countries used in Conditional Access.
  • Break-glass account: emergency admin excluded from Conditional Access.
  • Device object: the identity record for a device; states are registered, Entra joined, hybrid joined.
  • Entra Connect: sync bridge between on-premises AD and Entra ID; sync flows on-premises to cloud.
  • PHS: password hash sync; the cloud authenticates, resilient to on-premises outages.
  • PTA: pass-through authentication; on-premises AD validates at sign-in, nothing stored in the cloud.
  • Identity Protection: automated risk detection and response for sign-ins and accounts (requires P2).
  • Administrative unit: delegated administration over part of the directory (requires P1).

Scenario self-test

Cover the answers, work each scenario, then check yourself below.

Scenario 1. Finance wants each of 4 departments to get its own Azure invoice, and developers must have no access to production. What is the simplest design?

Scenario 2. The security team wants to block virtual machine creation in West Europe and allow only approved VM sizes everywhere else. RBAC or Azure Policy?

Scenario 3. All administrators must complete MFA at every sign-in, and sign-ins from outside the corporate IP ranges must be blocked for the finance app. Which feature, and what are the assignment and grant pieces?

Scenario 4. A hospital is migrating from on-premises Active Directory. Workstations must keep single sign-on to the on-premises file shares, but new clinic laptops are cloud only. Which join types, and which Entra Connect sign-in method keeps the clinics working during a WAN outage?

Scenario 5. Each clinic manager must reset passwords for their own clinic's staff and nobody else's. The company refuses to create a second tenant. What do you build, and what license does it need?

Scenario 6. Users are signing in from unusual locations at odd hours. The company wants the response automated: step up to MFA on medium risk, block on high risk. Which feature, which policy type, and what license?

Answers

  1. Separate subscriptions per department, with developers given Contributor only on the dev subscription. Subscriptions are the billing boundary and a clean access boundary.
  2. Azure Policy. RBAC answers "who can do what"; only Policy answers "what is allowed to exist and where."
  3. Conditional Access. Policy 1: Users = directory role Global Administrator, Target = all cloud apps, Grant = require MFA. Policy 2: Target = finance app, Conditions = locations excluding the corporate named location, Grant = block. P1 required; exclude a break-glass account.
  4. Hybrid joined for the workstations (on-premises AD plus cloud registration), Entra joined with Autopilot for the new laptops. Password hash synchronization, because authentication happens in Entra ID and survives the outage.
  5. Administrative units, 1 per clinic, with the User Administrator role scoped to each AU. Requires P1.
  6. Identity Protection (P2), sign-in risk policy: medium risk requires MFA, high risk is blocked.
