The concept

Most organizations adopting Azure already have an on-premises Active Directory full of users, groups, and passwords. Microsoft Entra Connect is the bridge: it synchronizes those on-premises identities into Entra ID so each person has 1 identity that works everywhere.

What it does:

  • Synchronizes directory objects: users, groups, contacts, and devices flow from on-premises AD into Entra ID.
  • Connects the sign-in method: you choose how users authenticate. The 3 options are password hash synchronization (Day 36), pass-through authentication (Day 37), or federation with AD FS.
  • Enables single sign-on: Seamless SSO gives domain-joined devices silent sign-in to cloud apps without retyping passwords.
  • Optional extras: password writeback (lets cloud password changes flow back on-premises; requires P1) and device writeback (for hybrid join scenarios).

2 flavors:

  • Entra Connect Sync: the classic full server. Most features, most control, runs on a dedicated on-premises server.
  • Entra Cloud Sync: a lightweight provisioning agent. Simpler to deploy, good for multi-forest environments, but fewer advanced options.

2 setup modes:

  • Express: 1 on-premises forest, under 100,000 objects, password hash sync plus Seamless SSO with defaults. The fast path.
  • Custom: choose your sign-in method, filter which OUs sync, enable optional features, set up staging.

How it runs day to day: sync happens on a schedule, every 30 minutes by default. You can run a second server in staging mode as a hot standby: it imports and syncs everything but exports nothing, and you promote it if the primary fails.

The exam's core facts: synchronization flows 1 way, on-premises to cloud, by default. Password writeback is the deliberate exception. Only 1 active sync server per tenant (plus staging).

Key vocabulary

  • Microsoft Entra Connect: the sync bridge between on-premises AD and Entra ID.
  • Entra Connect Sync: the classic full-featured sync server.
  • Entra Cloud Sync: the lightweight agent-based alternative.
  • Express vs Custom settings: fast defaults vs full control over sign-in method and filtering.
  • Staging mode: a standby sync server that imports everything but exports nothing.
  • Seamless SSO: silent sign-in to cloud apps from domain-joined devices.
  • Password writeback: cloud password changes synced back on-premises (requires P1).
  • Sync cycle: the scheduled sync run, every 30 minutes by default.

Try it

Review-based lab. No on-premises AD needed, and nothing changes.

In the portal:

  1. Microsoft Entra admin center > Identity > Hybrid management > Microsoft Entra Connect. Check the sync status card: is sync enabled, when was the last sync, and which sign-in method is configured (password hash sync, pass-through auth, or federation)?
  2. Note which optional features show as enabled: Seamless SSO, password writeback, device writeback.
  3. If Connect Health is available in your tenant, open it and look at the sync error tiles. A healthy tenant shows zero export errors.

Concept check (on paper): for each requirement, pick Express or Custom setup: (a) single forest, 5,000 users, defaults are fine; (b) only 2 of 10 OUs should sync; (c) the company wants pass-through authentication instead of password hash sync.

Clean up: nothing was changed.

Worked example: Meridian Health

Meridian Health runs Entra Connect Sync in Custom mode on a dedicated server, with a second server in staging mode at the backup data center. They chose password hash synchronization (cloud authentication keeps clinics working during WAN outages), enabled Seamless SSO for the hospital workstations, and turned on password writeback so the self-service password reset portal (Day 28) works for synced users too. Only the Staff and Clinical OUs sync; service accounts and the old Test OU are filtered out.

Exam tip

The exam tests the sign-in method decision more than the sync mechanics. Anchor each method: password hash sync means the cloud authenticates (resilient), pass-through means on-premises authenticates (policy control), federation means full on-premises control with the most complexity. Days 36 and 37 make this choice concrete.

Key takeaways

  • Entra Connect gives hybrid users 1 identity across on-premises AD and Entra ID.
  • 2 flavors: full Connect Sync server or lightweight Cloud Sync agent.
  • Express for simple single-forest setups; Custom when you need filtering or a non-default sign-in method.
  • Sync runs every 30 minutes; staging mode provides a hot standby.
  • Sync flows on-premises to cloud by default; password writeback is the exception and needs P1.
