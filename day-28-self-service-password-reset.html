The concept

Password resets are the number 1 helpdesk ticket in most organizations. Self-service password reset lets users reset a forgotten password themselves, after proving who they are with registered authentication methods. Fewer tickets, faster recovery, happier users.

There are 2 separate pieces, and the exam tests the difference:

  • SSPR for users. A user who forgot their password goes to the reset portal, verifies with their registered methods (Microsoft Authenticator notification, phone call, SMS, or security questions for the legacy flow), and sets a new password. For cloud-only users this needs no premium license.
  • Password writeback. In a hybrid environment, a cloud password reset needs to flow back down to on-premises AD, or the user ends up with 2 different passwords. Writeback requires Microsoft Entra ID P1 or P2 plus Entra Connect with writeback enabled. No writeback, no SSPR for synced users: the reset would only change the cloud password.

Enabling SSPR is a 3-step configuration under Protection > Password reset:

  1. Properties. Choose who gets SSPR: None, a Selected group (the recommended pilot approach), or All.
  2. Authentication methods. Choose how many methods are required (1 or 2; 2 is the secure choice) and which methods are allowed.
  3. Registration. Users must register their methods before they can use SSPR, at the combined registration page. An unregistered user hitting the reset portal gets told to contact the admin: registration is the prerequisite people forget.

Also know the knobs: notify users on password resets (yes, always), and re-confirmation after a number of days (default 180), which prompts users to keep their methods current.

Admin-initiated reset is different from SSPR: an admin resetting a password in the portal is a privileged action, and in a hybrid setup it also depends on writeback to reach on-premises AD.

Key vocabulary

  • SSPR: self-service password reset. Users reset forgotten passwords after verifying with registered methods.
  • Password writeback: syncs a cloud password reset down to on-premises AD. Requires P1 or P2 plus Entra Connect.
  • Authentication methods: how the user proves identity during reset: Authenticator app, phone call, SMS.
  • Registration: the 1-time setup where users enroll their verification methods. Required before SSPR works.

Try it

Free. You enable SSPR for a pilot group, configure it, then revert.

In the portal:

  1. Create a security group called SSPR-Pilot and add your lab test user (Identity > Groups > New group, Assigned membership).
  2. Open Protection > Password reset > Properties. Set Self service password reset enabled to Selected, pick the SSPR-Pilot group, and save.
  3. Open Authentication methods. Set Number of methods required to reset to 2. Allow the mobile app notification and phone call methods. Save.
  4. Open Registration. Confirm Require users to register when signing in is Yes, and note the 180 day re-confirmation setting.
  5. Revert: set Self service password reset enabled back to None and save. Delete the SSPR-Pilot group and the test user.

Clean up: SSPR disabled again, pilot group and test user deleted. The tenant is exactly as you found it.

Worked example: Meridian Health

Meridian Health's helpdesk handled 90 password tickets a month, most at shift change when nurses could not wait. The admin pilots SSPR for the 40-person night shift group: enables it for the Selected group, requires 2 methods (Authenticator app plus SMS fallback), and has everyone register during onboarding. Night shift password tickets drop to nearly zero within a month, and the admin rolls SSPR out to All users. Because Meridian is hybrid, the admin also confirms password writeback is enabled in Entra Connect with P1 licenses, so a reset reaches the on-premises AD account too.

Check your understanding

  1. A synced user resets their password in the cloud but the old password still works on-premises. What is missing?
  2. You enable SSPR for All users, but a new hire gets "contact your administrator" at the reset portal. Why?
  3. Which is more secure for the number of methods required to reset: 1 or 2, and why?
  4. Your company is hybrid with no P1 licenses. Can synced users use SSPR?

Exam tip

Writeback is the exam's favorite SSPR trap: hybrid plus SSPR always raises the question "does the reset reach on-premises AD," and the answer is password writeback with P1 or P2. The second trap is registration: SSPR silently fails for users who never registered their methods.

Key takeaways

  • SSPR lets users reset forgotten passwords after verifying with registered authentication methods.
  • Pilot with a Selected group before enabling for All; require 2 methods.
  • Users must register their methods before SSPR works for them.
  • Password writeback (hybrid) requires P1 or P2 plus Entra Connect; without it, synced users cannot use SSPR properly.
  • SSPR for cloud-only users needs no premium license.
