The concept

An assignment takes a policy definition and switches it on at a scope. 1 definition can have many assignments: the same "Allowed locations" rule can allow 2 regions on production and 1 region on development.

When you create an assignment, you configure 5 things:

  1. Scope: a management group, subscription, or resource group. Everything under that scope is evaluated.
  2. Exclusions: child scopes to skip. For example, assign at the subscription but exclude the networking resource group that legitimately spans regions.
  3. Parameters: the values for the definition's parameters, such as the actual list of allowed locations.
  4. Enforcement mode: Default means the effect applies (Deny blocks, Audit flags). DoNotEnforce means Azure evaluates and reports compliance but takes no action. DoNotEnforce is how you pilot a Deny policy safely and measure what it would have blocked.
  5. Non-compliance messages: a custom message shown to users when a deployment is denied, so they know who to contact instead of guessing.

2 special cases:

  • Managed identity: the DeployIfNotExists and Modify effects change resources, so the assignment needs an identity with permission to make those changes. The assignment wizard can create a system-assigned managed identity for you, and you grant it the needed role.
  • Exemptions: separate from exclusions. An exemption is a time-bound waiver for specific resources, such as approving 1 legacy VM to stay non-compliant until its migration date.

After assignment, new and changed resources are evaluated immediately. Existing resources are picked up by the periodic compliance scan, so give the dashboard time to fill in.

Key vocabulary

  • Assignment: a definition applied to a scope, with parameters and settings.
  • Enforcement mode: Default (enforce the effect) or DoNotEnforce (evaluate and report only).
  • Exclusion: a child scope skipped by the assignment.
  • Exemption: a time-bound waiver for specific non-compliant resources.
  • Non-compliance message: custom text shown when a deployment is denied.
  • Managed identity: the identity an assignment uses to remediate resources for DeployIfNotExists and Modify effects.

Try it

You need any Azure account, including a free 1. You will walk the assignment wizard and cancel before creating anything.

In the portal:

  1. Open Policy, then Assignments, then select Assign policy.
  2. In Basics, pick your lab subscription as the scope and search for the "Allowed locations" definition.
  3. Open the Parameters tab and look at the allowed locations list you would fill in.
  4. Open the Enforcement tab and note the choice between Default and DoNotEnforce.
  5. Cancel the wizard without creating the assignment. Nothing is enforced.

In the CLI (Cloud Shell is fine):

  1. List existing assignments and their enforcement mode: az policy assignment list --query "[].{Name:name, Enforcement:enforcementMode}" --output table

Clean up: the wizard was cancelled, so nothing was created.

Worked example: Meridian Health

Meridian assigns "Allowed locations" with a Deny effect at the Meridian-Prod subscription. They do it in 2 steps. First, they assign with enforcement set to DoNotEnforce and watch the compliance dashboard for a week to see what would have been blocked. 2 shared services would have broken, so they add exclusions for those resource groups. Then they flip enforcement to Default. Piloting with DoNotEnforce turned a risky rollout into a non-event.

  2. Which 2 effects require a managed identity on the assignment, and why?
  3. What is the difference between an exclusion and an exemption?
  4. A definition has a required parameter with no default value. What must every assignment of that definition provide?

Exam tip

"Pilot a policy safely" or "see what would be blocked" always means DoNotEnforce. "Automatically deploy a missing agent or setting" means DeployIfNotExists plus a managed identity plus a remediation task (Day 14). And remember: assignments need parameters whenever the definition declares required ones.

Key takeaways

  • An assignment applies 1 definition to 1 scope: management group, subscription, or resource group.
  • Configure scope, exclusions, parameters, enforcement mode, and non-compliance messages.
  • DoNotEnforce lets you measure impact before a Deny policy goes live.
  • DeployIfNotExists and Modify need a managed identity with write permission.
  • Use exclusions for permanent skips and exemptions for time-bound waivers.
