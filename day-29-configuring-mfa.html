The concept

Passwords get phished, guessed, and reused. Multi-factor authentication fixes that by requiring a second proof: something you know (password) plus something you have (phone, token) or something you are (biometric). Microsoft's data has consistently shown MFA blocks the overwhelming majority of account compromise attacks, which is why the exam treats it as non-negotiable.

Authentication methods you can offer users, strongest first:

  • Microsoft Authenticator with number matching. The app shows a number; the user taps the matching 1 on their phone. Number matching defeats "MFA fatigue" attacks where attackers spam push approvals hoping the victim taps yes.
  • FIDO2 security keys. Phishing-resistant hardware keys. The gold standard for admins.
  • Certificate-based and Temporary Access Pass. A time-limited passcode that bootstraps passwordless sign-in for new hires and recovery.
  • OATH hardware tokens. Time-based 1-time codes from a physical token.
  • Phone call and SMS. Better than nothing, but the weakest: SIM swapping and interception are real. The exam ranks these below app-based methods.

3 ways to enforce MFA, and the exam wants you to rank them:

  1. Conditional Access policies (Day 31). The modern, recommended way: "require MFA for all cloud apps when signing in from outside the office." Needs P1 or P2.
  2. Security Defaults (Day 30). The free baseline: MFA for everyone, no customization. The answer when there are no premium licenses.
  3. Per-user MFA. The legacy switch: each user set to Disabled, Enabled, or Enforced. Microsoft recommends moving off it to Conditional Access. Know the states: Enabled means the user is prompted to register at next sign-in; Enforced means they already registered and MFA applies every time.

Combined registration. SSPR (Day 28) and MFA share 1 registration experience now: users register their methods once at the combined registration page, and the same methods serve both password reset and MFA challenges.

Key vocabulary

  • MFA: multi-factor authentication. 2 or more proofs required at sign-in.
  • Number matching: the Authenticator flow where the user taps the number shown on screen, defeating approval spam.
  • Per-user MFA: the legacy per-account MFA switch with Disabled, Enabled, and Enforced states.
  • Conditional Access: policy engine that enforces MFA based on signals like user, device, and location (P1 or P2).
  • Temporary Access Pass (TAP): a short-lived passcode used to bootstrap strong authentication.

Try it

Free. You toggle per-user MFA for a test user and revert it.

In the portal:

  1. Create a test user if you do not have 1 left over from Day 23 (Identity > Users > New user).
  2. Open Identity > Users > All users and click the Per-user MFA button at the top. This opens the classic MFA management page.
  3. Select your test user and click Enable. Note the state column changes to Enabled: at next sign-in the user would be prompted to register methods.
  4. Select the user again and click Disable to revert. The state returns to Disabled.
  5. Delete the test user.

What not to touch in this lab: do not set any real user to Enforced, and do not change the tenant's Security Defaults or Conditional Access. This lab is per-user state on a throwaway account only.

Clean up: test user deleted, per-user MFA back to Disabled. Tenant MFA posture unchanged.

Worked example: Meridian Health

After the phishing incident in Day 23's story, Meridian's security team mandates MFA for all 400 staff. They do it in layers: Security Defaults would be too blunt (they have P1), so they write a Conditional Access policy requiring MFA for all cloud apps, with the Microsoft Authenticator app as the primary method and number matching enforced. The 5 global admins get FIDO2 keys instead of phones. Helpdesk tickets spike for 2 weeks during registration, then account compromise incidents fall off a cliff. The CISO's board slide writes itself.

Exam tip

The exam's MFA questions are really license questions in disguise: "no premium licenses" means Security Defaults; "P1 available" means Conditional Access; per-user MFA appears mostly as the legacy option to avoid. Also memorize the method ranking: FIDO2 and Authenticator with number matching beat SMS every time.

Key takeaways

  • MFA requires a second proof at sign-in and blocks the vast majority of account compromises.
  • Method strength: FIDO2 and Authenticator with number matching beat OATH tokens, which beat phone call and SMS.
  • Enforce with Conditional Access (P1 or P2, recommended), Security Defaults (free baseline), or per-user MFA (legacy: Disabled, Enabled, Enforced).
  • SSPR and MFA share combined registration: 1 enrollment covers both.
  • Number matching defeats MFA fatigue approval spam.
